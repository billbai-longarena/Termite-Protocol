# SwarmWorld 与白蚁协议：环境中介型 Agent 协作的两条研究路径

> 2026-08-31 基于论文 arXiv v1 整理。

## 一句话定位

[SwarmWorld](https://doi.org/10.48550/arXiv.2608.26081) 是研究语言模型 Agent 如何通过持久化环境形成技术社会的受控科学实验；白蚁协议是把环境中介协作应用到真实软件仓库、跨会话无状态编码 Agent 上的工程协议。

两者不是同一个系统，也不应把任何一方描述成对另一方的直接验证。更准确的关系是：**两条独立发展的路径汇合到同一个方向——持久化环境可以承载 Agent 的协调、记忆与能力积累。**

## 研究关系与公开时间线

白蚁协议的公开 Git 历史始于 **2026-02-23**；SwarmWorld 的 arXiv v1 提交于 **2026-08-26**。我们没有在论文 v1 正文中发现对白蚁协议的引用。但公开时间先后不能证明双方存在影响关系：研究与实现通常早于正式发布，而且两个项目都建立在更早的信息素协作、黑板系统、分布式系统和群体智能传统之上。

因此，本仓库将 SwarmWorld 作为相关研究和独立外部证据引用，不主张优先权、背书、复现或直接传承关系。

## 二者的共同方向

| 主题 | SwarmWorld | 白蚁协议 | 共同方向 |
| --- | --- | --- | --- |
| 环境作为协调介质 | Agent 改变持久化空间世界，后来的 Agent 感知已经改变的状态。 | Agent 读取和修改仓库、SQLite 信号、Git 历史、文档、测试和 `.birth`。 | 协调可以存在于环境中，而不必依赖不断增长的对话。 |
| 外部化记忆 | 持久制品保存构造、状态、来源和可执行控制器。 | 代码、commit、观察、规则、WIP 和黑板保存跨会话知识。 | 有价值的工作应当在执行它的 Agent 离开后继续存在。 |
| 累积式继承 | Agent 观察、复用、fork 并扩展其他 Agent 的可执行程序。 | 后继 Agent 复用代码、模板、规则和高质量行为范式。 | 能力可以通过持久制品和可追踪修改不断积累。 |
| 行为分化 | 初始同质 Agent 逐渐形成探索、建造、维护和协调行为。 | Agent 根据场状态进入或退出 scout、worker、soldier、nurse 工作模式。 | 有效群体需要可随时间变化的差异化行为。 |
| 来源与后果 | 确定性模拟器将 Agent 的声称与真实功能分开，并记录事件谱系。 | Git、测试、CI、权限、信号历史和审计包将声称与可检查证据分开。 | Agent 说了什么不够，后果和来源必须可观察。 |
| 群体目标 | 共享社会在组合广度和韧性上更强，独立搜索仍可能保留最强单件制品。 | 白蚁协议优化连续性、覆盖率、可恢复性和混合 Agent 参与，而不是假定所有任务都需要一个全局最强 Agent。 | 群体价值往往体现为组合韧性，而不只是单个最优答案。 |

SwarmWorld 有几项结果对白蚁协议尤其重要：

- 共享世界相对于强力的 best-of-N 独立搜索基线，产生了更广、更有韧性的技术组合；但独立搜索仍可能找到性能最强的单件制品。
- 约 95% 的制品首次复用来自后来 Agent 对环境中制品的直接观察，而不是发明者对采用者的直接沟通。
- Agent 没有永久角色，却会随着世界成熟形成并切换探索、建造、维护和协调等行为。
- 移除显式文化机制后，群体仍能通过持久制品的信息素协作形成有效协调。
- 形成的网络能抵抗随机 Agent 流失，但对高度连接的关键节点被定向移除更敏感，说明分布式韧性与枢纽风险会同时出现。

这些结果加强了环境优先架构的合理性，同时也提醒我们：更多沟通、更多编排或更多 Agent 并不必然带来更好的结果。

## 二者的重要差异

| 维度 | SwarmWorld | 白蚁协议 |
| --- | --- | --- |
| 主要目的 | 研究群体技术演化的科学实验平台。 | 服务真实软件工程工作的协作协议。 |
| 环境 | 包含空间、材料、资源、环境场和扰动的确定性模拟世界。 | 软件仓库及其运行状态：文件、Git、SQLite、测试、CI 和工具输出。 |
| Agent 群体 | 使用相同模型、提示词、能力和预算的初始同质 Agent。 | 明确面向能力和工具不同的异质模型协作。 |
| 角色机制 | 不预设角色；实验结束后从行为中识别角色。 | 种姓是由当前状态和权限规则选出的操作模式，不是永久身份。 |
| 沟通方式 | 完整文化条件包含消息、发表、教学、交易、任务认领和程序继承，并通过消融实验逐项移除。 | 通常没有 Agent 间直接对话。Agent 会有意给后继者留下信号、规则和 WIP，所以更准确地说是“环境中介的显式通信”，而不完全等于物理信息素协作。 |
| 后果裁决 | 封闭模拟器权威判断动作是否合法、制品是否有效，并执行移除 Agent 后的未见扰动测试。 | 由宿主项目的测试、构建、运行检查、代码评审和生产结果裁决，但协议本身没有统一封闭模拟器。 |
| 记忆模型 | 单个模拟社会中存在有界私有记忆和按实验条件开放的共享记录。 | 把 Agent 会话视为可抛弃，通过到达时读取共享环境重建连续性。 |
| 证据等级 | 有受控消融、匹配种子、独立基线、不可变轨迹和留出评估。 | 目前主要是生产现场观察和多模型审计，具有工程证据价值，但还不等同于受控科学复现。 |
| 独有机制 | 物理制品、资源约束、可执行控制器和环境扰动。 | 信号权重与 TTL、蒸发、质量加权规则涌现、原子认领、上下文蜕皮和安全权限边界。 |

角色差异尤其重要。SwarmWorld 证明的是初始同质 Agent 可以自然形成分工；白蚁协议的种姓则是安全与路由机制，由环境状态显式选择。二者行为结果相似，但因果机制不同。

“信息素协作”的含义也不完全一样。SwarmWorld 最典型的是间接物理协调：一个 Agent 改变世界，另一个 Agent 后来发现其后果。白蚁 Agent 写信号、规则或 WIP 时，通常明确知道后继者会读取，因此它仍是环境中介协作，但更多属于通过环境进行的有意符号通信。

## 双方分别贡献了什么

SwarmWorld 提供了更严格的实验语言和基线设计：

- 用 endpoint-wise best-of-N 独立搜索对照共享社会；
- 把方案陈述与独立测量的后果分开；
- 移除 Agent 后继续测试技术组合；
- 测量采用、谱系、角色切换、网络记忆和枢纽脆弱性；
- 用消融实验区分物理信息素与显式文化通道。

白蚁协议提供了把这一方向用于真实仓库的工程机制：

- 用有界 `.birth` 快照降低新会话到达成本；
- 用 SQLite WAL 信号和事务实现原子任务认领；
- 用 Git 来源链和 WIP 实现跨会话交接；
- 用质量加权沉积、蒸发和规则提升治理环境知识；
- 用权限边界和恢复规则约束实际操作；
- 用持久化行为模板支持强弱模型混合协作。

二者可以共同支持的最强结论，应当保持克制：

> 持久化环境不只是上下文仓库。当环境保存有后果的制品、来源关系和可复用结构时，它可以成为语言模型 Agent 群体主动协调与继承能力的基础设施。

## 共同研究议程

SwarmWorld 为白蚁协议下一步实验提供了很好的方法框架：

1. **匹配消融实验**：在相同任务和模型调用预算下，对比完整白蚁协议、仅共享仓库、去掉行为模板的信号系统，以及 best-of-N 独立编码 Agent。
2. **移除 Agent 的留出评估**：Agent 完成工作后，不再允许模型介入，运行未见测试、故障注入、升级任务或可维护性探针。
3. **制品采用指标**：测量代码、规则和模板的首次复用时间、非作者复用人数、fork 深度和下游覆盖。
4. **动态角色对照**：比较由状态分配种姓的条件，与完全不提供种姓引导、允许分工自行涌现的条件。
5. **网络韧性测试**：模拟随机 Agent 流失，以及定向移除高中心度维护者、模板或知识枢纽。
6. **组合指标**：除了最佳单个 patch 的质量，同时评估覆盖广度、韧性和恢复能力。

这些实验可以检验：SwarmWorld 在模拟材料社会中观察到的规律，有多少能迁移到真实软件工程环境；又有哪些机制只属于其中一个领域。
